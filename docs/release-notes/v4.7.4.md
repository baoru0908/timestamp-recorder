# TimestampRecorder v4.7.4

> 一个**只修一处首页定位问题**的修复版。没有新功能、没有新交互、没有新依赖；
> **数据与备份格式（format 2）完全不变**，老用户的事件、记录、颜色、导入导出
> **全部不受影响**，无需任何迁移。

本版修复：**冷启动 / 后台复活进入首页时，事件列表可能停在中间（而不是最顶端）**。

---

## 🐞 修复

### 1. 首页事件列表在冷启动 / 后台复活时不回到顶部

- **问题**：从桌面图标打开、或进程被系统回收后从最近任务切回首页时，
  「事件」列表偶尔停在**上次停留的中间位置**，而不是最顶端。
- **根因**：`MainActivity` 会让系统**自动恢复 `RecyclerView` 的滚动位置**
  （默认行为，`onRestoreInstanceState` 在数据装载之前先把位置还原），
  且没有任何一处主动置顶 —— 于是只要带回了实例状态，位置就会被还原到上次处。
- **修复**：区分两种「重新进入」，按用户预期分别处理：

  | 场景 | 行为 |
  |:---|:---|
  | **冷启动**（划掉任务后打开 / `force-stop`） | 回到**最顶端** |
  | **进程被回收后从最近任务复活** | 回到**最顶端** |
  | **旋转屏幕 / 切深浅色 / 字体缩放**（配置变更） | **保留当前位置** |
  | **从详情页返回 / 切换底部 Tab** | **保留当前位置** |

- **做法**：在 `onSaveInstanceState` 里记录 `isChangingConfigurations`
  （官方语义：配置变更时为 `true`，进程被回收时为 `false`），
  重建时据此判断 —— 配置变更保留位置，冷启动 / 复活则在首个数据装载完成后显式置顶。
  **未改动 `android:saveEnabled`**（关掉它会连「旋转保留位置」一起破坏）。
  事件列表与时间线列表**均已处理**。

## 🔧 说明

- 改动集中在 `MainActivity` 的状态处理与首个数据装载时序，**不涉及数据层**；
  事件色板数值、CSV 导出、备份格式（format 2）**均未改动**。

- `minSdk 24` / `targetSdk 34` 不变；**依旧零权限、完全离线**。
- **数据与备份格式完全没有改动**（format 2），v4.7.3 的备份可直接导入。

- 签名指纹不变（`cca83079…f8f976ce`），可直接覆盖安装。
