# TimestampRecorder v4.7.0

> 一个**只动取色器、不动数据**的小版本：给自定义颜色加了「直接输入色号」入口，并放开了明度上限，
> 现在可以选到纯白与任意高亮浅色。事件色板数值未改，备份格式仍是 format 2，
> 老用户的事件颜色、圆点、时间线渐变色、图表柱色、导入导出**全部不受影响**，无需任何迁移。

自定义颜色以前只能「拖」，而且明度被悄悄压在「白字还看得清」的上限内。这版把这两点都放开：
**既可直接键入十六进制色号，也能选到完整 0~100% 明度（含纯白）**。

---

## ✨ 新功能：取色器支持色号输入 + 完整亮度范围

### 1. 颜色编码输入框

- **你能做什么**：取色器标题下方新增一个输入框，可**直接键入颜色的十六进制编码**，回车即应用。
  支持 `#RRGGBB`（如 `#1E88E5`）、`RRGGBB`（`#` 可省略）、`#RGB` 简写（如 `#0AF` 等于 `#00AAFF`），
  也接受 `#AARRGGBB`（忽略前两位透明度 —— 本 App 的事件色恒为不透明）。大小写都行。
- **为什么加**：精确复刻某个品牌色号、或从别处抄来一个 `#` 开头的色值时，纯靠拖动很难对准；
  能直接输入最省事。
- **怎么做到**：输入框内容变化时解析。

  - **非法或只敲了一半（如 `#F`）会静默忽略** —— 不弹错、不打断打字，格式提示常驻在输入框下方；
  - 拖动色盘 / 色相条时会**反向回填**输入框当前颜色，用一个内部标志挡住回填触发的二次解析，
    避免「输入框 ↔ 色盘」来回递归。

### 2. 完整亮度范围（可选到纯白）

- **你能做什么**：SV 方块纵向现在是**完整 0~100% 明度**，可以选到**纯白**与任意高亮浅色；
  此前纵向被限制在「白字仍能达标」的上限内，选不到这些颜色。
- **怎么做到**：移除了面板明度上的「白字上限」收口（并顺带清掉配套的缓存 / 插值死代码）。

### 怎么用

1. 新建 / 编辑事件 → 点色板里的「＋ / 自定义」入口，打开取色器；
2. 想手输色号：点中间输入框，键入 `#RRGGBB`（或 `#RGB` / `RRGGBB`）→ 按回车；
3. 想拖：拖上方色相条选色相，拖中间方块选「饱和度 × 明度」；方块越往上越亮，顶边即纯白；
4. 下方预览块实时显示当前色 → 点「确定」保存。

### 设计取舍（v1）

- **纯白 / 高亮底色上的文字会自动转近黑**：事件卡上的文字与图标颜色由 App 按底色明度**自动**选。
  放开亮度范围后，纯白与高亮浅色底上会由**白字转为近黑色**以保证看得清，
  于是**同一列事件里可能同时出现黑字与白字** —— 这是「支持完整亮度范围」换来的**有意代价**，
  不是 bug。v4.5.0 曾为保证「全 App 一套白字」否掉过这种混排，本次按用户要求重新放开。
- **本次不做**：不给单个事件单独设置前景文字颜色（仍由 App 按底色自动选），也不调整 23 色色板数值。

## 📦 数据与兼容

- `minSdk 24` / `targetSdk 34` 不变；**依旧零权限、完全离线**。
- **数据与备份格式完全没有改动**（format 2），v4.6.1 的备份可直接导入。
- **事件色板数值未改**，已存在事件的 `color` 整数一个都没动；签名指纹不变，可直接覆盖安装。
- 新增输入框的文案暂时直接写在代码里（未进 `strings.xml`），下次做多语言时统一迁移。
