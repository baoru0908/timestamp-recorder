# TimestampRecorder v4.6.0

> 一个**只动一条判定线、不动数据**的小版本。事件色板数值一个都没改，备份格式仍是 format 2，
> 老用户的事件颜色、圆点、时间线渐变色、图表柱色、导入导出**全部不受影响**，无需任何迁移。

事件色当作背景时，前景文字改用**更高的判定阈值**（相对亮度 > 0.60，原 0.45）：
**白字覆盖更多场景**，全 App 的文字观感更统一、更少出现同一列里黑白混排的情况。

---

## 🎨 事件色文字：白字一致性优先

- **判定线上调**：底色相对亮度 **> 0.60** 才把前景转深色字，其余一律白字（原为 0.45）。
  语义是「**白字优先 / 一致性优先**」—— 更少底色会转成深色字，白字覆盖更多场景。
- **用户可见的变化只有一处**：

  > 23 个预设色里**只有「琥珀 `#F9A825`」一种会变**：文字由深色变白色，
  > 清晰度从 8.67:1 变为 1.97:1（偏淡）；**其余 22 个颜色显示完全不变**。
  > 纯白与明黄仍为深色字，不会糊。
  > 连带：选色板中琥珀色块的**选中圆环**也由深色变白色，选中态在该色上不太明显。
  > 另：亮青 / 橙 / 浅蓝 / 青 / 薄荷上的白字本就偏淡（2.30 ~ 2.9985:1），
  > **属改动前既有情况，非本次引入**。

- 方向说明：更高阈值意味着浅底上的白字可读性**会下降**，琥珀即是这一取舍的代价。
  本次选择是「**一致性优先**」—— 全 App 一套白字，而不是逐色挑选黑白。

## 🔧 技术说明

- 改动集中在 `EventRepository` 的常量 **`LIGHT_BACKGROUND_LUMINANCE = 0.60`**（原 0.45）。
- **`WHITE_TEXT_MIN_CONTRAST`（4.5）与取色器逻辑未动**：自定义取色器产出的颜色受
  `maxValueForWhite` 约束（亮度 ≤ 0.1833），新旧阈值下都是白字，**不受本次改动影响**。
- 纯白 `#FFFFFF`（白字 1:1）与明黄 `#FDD835`（1.40:1）仍然转深色字，兜底不变。
- 同步修正了 4 处随阈值失效的旧注释（`MainActivity` / `EventDetailActivity` /
  `ColorAdapter` / v4.5.0 发布说明的时效注记），均为纯文案、无逻辑改动。

## 📱 兼容性

- `minSdk 24` / `targetSdk 34` 不变；**依旧零权限、完全离线**。
- 数据与备份格式**完全没有改动**（format 2），v4.5.0 的备份可直接导入。
- **事件色板数值未变**，已存在事件的 `color` 整数一个都没动；前景色是运行时计算，
  所以升级后**琥珀事件会自动变白字**，无需任何手动操作。
- 签名指纹不变（`cca83079…f8f976ce`），可直接覆盖安装。
